      DevOps Interview Prep

      60 real interview questions with concise model answers, from Linux basics to Kubernetes internals and incident scenarios.

      How to use this page

      Read the question and answer it out loud before expanding the model answer. Interviewers care about your reasoning and trade-offs, not memorised wording. For scenario questions, talk through how you would investigate before you jump to a fix.

      🐧 Linux & Shell (7)

      BeginnerWhat is the difference between a process and a thread?

      A process is a running program with its own memory space, file descriptors and PID. A thread is a unit of execution inside a process; threads share the process's memory and resources, so they are cheaper to create but need synchronisation. On Linux both are scheduled as tasks, and threads are created with clone() sharing the address space.

      BeginnerHow do Linux file permissions work? What does chmod 750 mean?

      Each file has read (4), write (2) and execute (1) bits for owner, group and others. 750 = owner rwx (7), group r-x (5), others nothing (0). On directories, x means you can enter it and r means you can list it.

      BeginnerWhat does load average mean in the output of uptime?

      The average number of tasks running or waiting (runnable or in uninterruptible I/O wait) over 1, 5 and 15 minutes. Compare it to the CPU count: a load of 4 on a 4-core box means fully busy; 8 means work is queuing. A high load with low CPU usage usually points to I/O wait.

      IntermediateA disk is full but du shows much less usage than df. Why?

      Usually a process still holds a deleted file open. The space is not freed until the file descriptor closes. Find it with lsof +L1 (or lsof | grep deleted), then restart the process or truncate it via /proc/<pid>/fd/<n>. Other causes: files hidden under a mount point, or reserved blocks on ext4.

      IntermediateWhat is the difference between a hard link and a symbolic link?

      A hard link is another directory entry pointing to the same inode; deleting the original name does not remove the data, and it cannot cross filesystems or point to directories. A symlink is a separate file containing a path; it can cross filesystems but breaks if the target is moved or deleted.

      IntermediateWhat does set -euo pipefail do in a Bash script?
      • -e exits on any command that fails
      • -u treats unset variables as errors
      • -o pipefail makes a pipeline fail if any command in it fails, not just the last

      Together they stop scripts from silently continuing after an error, which is critical in CI and automation.

      AdvancedWalk me through what happens when you type a command and press Enter.

      The shell parses the line (expansions, quoting, redirections), checks for builtins/aliases/functions, then searches $PATH. It calls fork() to create a child, the child sets up redirections and calls execve() to replace itself with the program, and the kernel loads the ELF binary (and dynamic linker). The parent wait()s for the exit status, available as $?.

      🌐 Networking (6)

      BeginnerWhat happens when you type a URL into a browser?
      1. DNS resolves the hostname to an IP (browser cache → OS → resolver → root → TLD → authoritative).
      2. TCP 3-way handshake (SYN, SYN-ACK, ACK) to port 443.
      3. TLS handshake: certificate verification and key exchange.
      4. The browser sends an HTTP request; load balancers/proxies route it to a server.
      5. The response is rendered and further resources are fetched.
      BeginnerWhat is the difference between TCP and UDP?

      TCP is connection-oriented, reliable and ordered, with retransmission and congestion control (HTTP/1.1–2, SSH, databases). UDP is connectionless with no delivery guarantee, so it is lower latency (DNS, video, gaming, and QUIC/HTTP/3, which builds reliability on top of UDP).

      BeginnerWhat does 10.0.0.0/16 mean, and how many addresses does it contain?

      CIDR notation: the first 16 bits are the network, leaving 16 bits for hosts, so 216 = 65,536 addresses (10.0.0.0–10.0.255.255). A /24 has 256. In AWS, 5 addresses per subnet are reserved.

      IntermediateWhat is the difference between an L4 and an L7 load balancer?

      An L4 load balancer routes by IP and port (TCP/UDP) without looking at content. It is fast and protocol-agnostic (AWS NLB). An L7 load balancer understands HTTP, so it can route by host, path or header, terminate TLS, and do retries and sticky sessions (AWS ALB, Nginx, Envoy).

      IntermediateExplain the main DNS record types you use day to day.
      • A/AAAA: name to IPv4/IPv6
      • CNAME: alias to another name (not allowed at the zone apex)
      • MX: mail servers
      • TXT: verification, SPF, DKIM
      • NS: delegates a zone
      • SRV: service host and port

      Remember TTLs: lower them before a migration so changes propagate quickly.

      AdvancedA service can't reach another service. How do you troubleshoot it, layer by layer?
      1. DNS: dig/nslookup the name. Does it resolve to the expected IP?
      2. Routing: ip route, traceroute/mtr.
      3. Port: nc -zv host port or curl -v. A timeout usually means a firewall or security group; "connection refused" means nothing is listening.
      4. Listener: ss -tlnp on the target. Is it bound to 0.0.0.0 or only 127.0.0.1?
      5. TLS/app: openssl s_client, then check the application logs.

      🌿 Git (4)

      BeginnerWhat is the difference between git merge and git rebase?

      Merge joins histories with a merge commit and preserves exactly what happened. Rebase replays your commits on top of another branch, giving a linear history but rewriting commit IDs. Rule of thumb: rebase your own local work, never rebase commits others have already pulled.

      BeginnerWhat is the difference between git fetch and git pull?

      git fetch downloads new commits and updates remote-tracking branches without touching your working branch. git pull is fetch followed by merge (or rebase with --rebase) into your current branch.

      IntermediateYou committed a secret to Git. What do you do?
      1. Revoke/rotate the secret immediately. Assume it is compromised the moment it was pushed.
      2. Remove it from history with git filter-repo or BFG, force-push, and ask collaborators to re-clone.
      3. Prevent recurrence: secret scanning (gitleaks, GitHub push protection), pre-commit hooks, and a secrets manager.
      IntermediateCompare trunk-based development with GitFlow.

      Trunk-based: short-lived branches (hours to a day) merged to main frequently, with feature flags hiding unfinished work. It enables continuous delivery and is what DORA research associates with high performance. GitFlow: long-lived develop, release and hotfix branches. It suits scheduled, versioned releases but adds merge overhead.

      🐳 Docker & Containers (6)

      BeginnerWhat is the difference between a container and a virtual machine?

      A VM virtualises hardware and runs a full guest OS with its own kernel on a hypervisor. A container is an isolated process that shares the host kernel, isolated with namespaces and limited with cgroups. Containers start in milliseconds and are much smaller; VMs give stronger isolation.

      BeginnerWhat is the difference between CMD and ENTRYPOINT?

      ENTRYPOINT defines the executable that always runs; CMD supplies default arguments (or the default command if there is no entrypoint). Arguments to docker run image ... replace CMD but are appended to ENTRYPOINT. Use the exec (JSON array) form so the process is PID 1 and receives signals.

      BeginnerCOPY vs ADD?

      Both copy files into the image. ADD can also fetch URLs and auto-extract local tar archives, which is surprising behaviour. Prefer COPY unless you specifically need tar extraction.

      IntermediateHow do you make Docker images smaller and builds faster?
      • Multi-stage builds: compile in one stage, copy only artifacts into a slim runtime image
      • Minimal bases: -slim, alpine or distroless
      • Order layers by change frequency: copy dependency manifests and install before copying source
      • A .dockerignore to keep .git and node_modules out of the context
      • Combine and clean up in the same RUN (e.g. remove apt lists)
      • BuildKit cache mounts for package managers
      IntermediateHow do namespaces and cgroups make containers work?

      Namespaces isolate what a process can see: PID, network, mount, UTS (hostname), IPC and user. cgroups limit what it can use: CPU, memory, I/O and PIDs. A container is just a process with its own namespaces, cgroup limits and a layered root filesystem (OverlayFS).

      AdvancedHow do you secure containers in production?
      • Run as non-root, with a read-only root filesystem, and drop all capabilities except those needed
      • Minimal or distroless base images, rebuilt regularly
      • Scan images (Trivy, Grype) in CI and block on critical CVEs
      • Sign images (Cosign) and verify signatures at admission
      • No secrets in images or env baked at build time; mount them at runtime
      • Seccomp/AppArmor profiles, and never --privileged or mounting the Docker socket

      ☸️ Kubernetes (8)

      BeginnerExplain the Kubernetes control plane components.
      • kube-apiserver: the front door; every component talks to it
      • etcd: consistent key-value store holding all cluster state
      • kube-scheduler: assigns pending Pods to nodes based on resources, affinity and taints
      • kube-controller-manager: runs control loops (Deployments, ReplicaSets, Nodes) that drive actual state to desired state
      • cloud-controller-manager: integrates load balancers and volumes with the cloud

      On each node: kubelet, kube-proxy (or an eBPF CNI replacement) and a container runtime (containerd).

      BeginnerWhat is the difference between a Deployment, a StatefulSet and a DaemonSet?
      • Deployment: interchangeable stateless replicas with rolling updates
      • StatefulSet: stable identities (db-0, db-1), per-replica persistent volumes, ordered rollout; for databases and brokers
      • DaemonSet: one Pod per node; for log shippers, node exporters and CNI agents
      BeginnerWhat are the Service types?
      • ClusterIP (default): a stable virtual IP inside the cluster
      • NodePort: exposes a port on every node
      • LoadBalancer: provisions a cloud load balancer
      • ExternalName: a DNS CNAME to an external name

      For HTTP routing to many services, use an Ingress or the newer Gateway API in front of ClusterIP services.

      IntermediateWhat is the difference between liveness, readiness and startup probes?
      • Readiness: is the Pod ready for traffic? Failing removes it from Service endpoints but does not restart it.
      • Liveness: is the process healthy? Failing restarts the container.
      • Startup: disables the other probes until a slow app has started.

      A common mistake is a liveness probe that checks dependencies (like the DB), which restarts every Pod when the database blips.

      IntermediateHow do resource requests and limits work, and what is QoS?

      Requests are what the scheduler reserves; limits are the cap. Exceeding the memory limit gets the container OOMKilled; exceeding the CPU limit gets it throttled. QoS classes: Guaranteed (requests = limits), Burstable and BestEffort (none set). Under node memory pressure, BestEffort Pods are evicted first.

      IntermediateHow does a rolling update work and how do you roll back?

      The Deployment creates a new ReplicaSet and scales it up while scaling the old one down, governed by maxSurge and maxUnavailable. Readiness probes gate progress. Roll back with kubectl rollout undo deployment/app (or --to-revision); in GitOps, revert the commit instead.

      AdvancedHow does Horizontal Pod Autoscaling work, and what are its pitfalls?

      The HPA controller periodically reads metrics (CPU/memory from metrics-server, or custom/external metrics) and computes desired = ceil(current × currentMetric / target). Pitfalls: no CPU requests set (utilisation can't be computed), scaling on CPU for I/O-bound apps, slow startup causing flapping, and no node capacity, which needs a Cluster Autoscaler or Karpenter.

      AdvancedHow do you secure a Kubernetes cluster?
      • RBAC with least privilege; no cluster-admin for apps; separate service accounts
      • Pod Security Admission (restricted profile), plus policy engines like Kyverno or OPA Gatekeeper
      • NetworkPolicies with default deny
      • Secrets encrypted at rest; External Secrets or a CSI driver for a real secrets manager
      • Private API endpoint, audit logging, image signing and verification, and regular upgrades

      🔁 CI/CD (4)

      BeginnerWhat is the difference between continuous integration, continuous delivery and continuous deployment?

      CI: every change is merged frequently and automatically built and tested. Continuous delivery: every change that passes is releasable, with deployment to production behind a manual approval. Continuous deployment: every change that passes goes to production automatically.

      IntermediateWhat makes a good CI/CD pipeline?
      • Fast feedback: run lint and unit tests first, parallelise, cache dependencies
      • Build once, promote the same artifact through environments
      • Security gates: SAST, dependency and image scanning, secrets detection
      • Pipeline as code, versioned with the app
      • Short-lived credentials (OIDC) instead of stored keys
      • Easy, tested rollback
      IntermediateCompare blue-green, canary and rolling deployments.
      • Rolling: replace instances gradually. Cheap, but both versions serve simultaneously.
      • Blue-green: two full environments with an instant traffic switch and instant rollback; doubles the cost during the cutover.
      • Canary: send a small percentage of traffic to the new version, watch metrics, then increase. Lowest blast radius; needs good observability (Argo Rollouts, Flagger).
      AdvancedHow do you authenticate CI to a cloud provider without storing long-lived keys?

      Use OIDC federation. The CI platform (e.g. GitHub Actions) issues a signed short-lived JWT for the job; the cloud (AWS IAM, GCP Workload Identity, Azure) trusts that issuer and exchanges the token for temporary credentials scoped to a role. Restrict the trust policy by repo, branch or environment (the sub claim).

      🏗️ Terraform & IaC (6)

      BeginnerWhat is Terraform state and why does it matter?

      State maps your configuration to real resource IDs and stores attributes, so Terraform can compute diffs. Teams store it remotely (S3, Terraform Cloud, GCS) with locking so two applies don't collide. It can contain secrets, so encrypt it and restrict access.

      BeginnerWhat is the difference between terraform plan and terraform apply?

      plan refreshes state, compares it to the configuration and shows what would change without changing anything. apply executes the changes (it plans again unless you pass a saved plan file). In CI, save the plan with -out and apply exactly that file after review.

      IntermediateWhat is configuration drift and how do you handle it?

      Drift is when real infrastructure no longer matches code, usually because of manual console changes. Detect it with scheduled terraform plan (a non-empty plan means drift). Then either codify the change or let apply revert it. Prevent it with read-only console access and policy.

      Intermediatecount vs for_each?

      count creates indexed copies ([0], [1]). Removing an item from the middle shifts indices and causes unwanted destroy/recreate. for_each keys instances by map keys or set values, so additions and removals only affect that item. Prefer for_each for anything with identity.

      AdvancedHow would you structure Terraform for multiple environments and teams?
      • Reusable, versioned modules (network, cluster, database)
      • Separate root configurations and separate state per environment and component, to keep the blast radius small
      • Remote state with locking; pin provider and module versions
      • Plan on PR, apply on merge, with policy as code (OPA/Conftest, Sentinel, Checkov)
      • Tools like Terragrunt, or Terraform Stacks, to reduce duplication
      AdvancedTerraform vs Ansible: when would you use each?

      Terraform is declarative and state-based, best for provisioning cloud resources and their lifecycle. Ansible is procedural, agentless over SSH, best for configuring machines (packages, files, services) and orchestration. Common pattern: Terraform creates VMs, Ansible configures them, though with immutable images (Packer) and containers, config management shrinks.

      ☁️ Cloud & AWS (5)

      BeginnerExplain regions, availability zones and why they matter.

      A region is a geographic area; an AZ is one or more isolated data centres within it, with independent power and networking. Spread workloads across at least 2–3 AZs for high availability; use multiple regions for disaster recovery or latency.

      BeginnerSecurity group vs network ACL in AWS?

      Security groups are stateful (return traffic is allowed automatically), allow-only, and attach to ENIs/instances. NACLs are stateless (rules needed in both directions), support allow and deny, are evaluated in order, and apply to whole subnets.

      IntermediateHow does a private subnet reach the internet?

      Through a NAT gateway in a public subnet (which routes to an Internet Gateway). The private route table sends 0.0.0.0/0 to the NAT, allowing outbound-only access. For AWS services, use VPC endpoints instead to save NAT data-processing cost and keep traffic private.

      IntermediateWhat is IAM least privilege, and how do you apply it?

      Grant only the actions on the resources that are needed. Use roles (not users with keys) for workloads, scope policies by resource ARN and conditions, use IAM Access Analyzer to generate policies from actual usage, and add permission boundaries or SCPs as guardrails.

      AdvancedHow would you reduce a large AWS bill?
      • Visibility first: Cost Explorer, cost allocation tags, per-team showback
      • Right-size over-provisioned instances (Compute Optimizer); move to Graviton
      • Commitments: Savings Plans or Reserved Instances for the steady baseline; Spot for stateless or batch work
      • Kill idle resources: unattached volumes, old snapshots, idle load balancers, dev environments overnight
      • Storage lifecycle policies; cut NAT and data-transfer costs with VPC endpoints

      📊 Monitoring & SRE (5)

      BeginnerWhat is the difference between monitoring and observability?

      Monitoring tells you whether known things are broken, using predefined dashboards and alerts. Observability lets you ask new questions about why, using rich telemetry: metrics, logs and traces (and profiles), ideally correlated via OpenTelemetry.

      BeginnerWhat are SLIs, SLOs and SLAs?

      SLI: a measured indicator (e.g. % of requests under 300 ms). SLO: an internal target for it (99.9% over 30 days). SLA: a contract with customers, with penalties, which is set looser than the SLO. The gap between 100% and the SLO is the error budget.

      IntermediateWhat are the RED and USE methods?

      RED (for services): Rate, Errors and Duration of requests. USE (for resources): Utilisation, Saturation and Errors of CPU, memory, disk and network. Google's four golden signals combine both: latency, traffic, errors and saturation.

      IntermediateHow do you avoid alert fatigue?
      • Alert on symptoms users feel (SLO burn rate), not every cause (CPU 80%)
      • Every page must be actionable, urgent and have a runbook
      • Route non-urgent issues to tickets, not pages
      • Use multi-window burn-rate alerts to cut flapping
      • Review alerts after incidents and delete noisy ones
      AdvancedWalk me through how you would run an incident.
      1. Declare it and assign roles: incident commander, communications, operations.
      2. Mitigate first: roll back, fail over, scale or shed load. Root cause can wait.
      3. Communicate on a regular cadence to stakeholders and the status page.
      4. Resolve, then hold a blameless postmortem: timeline, impact, contributing factors and action items with owners.

      🛡️ DevSecOps (4)

      BeginnerWhat does "shift left" mean in security?

      Moving security checks earlier in the lifecycle, into the IDE, pre-commit and pull request pipelines, so issues are caught when they are cheapest to fix. Examples: SAST, dependency scanning, IaC scanning and secret detection on every PR.

      IntermediateSAST vs DAST vs SCA?
      • SAST: analyses source code without running it (Semgrep, CodeQL)
      • DAST: attacks the running application from outside (OWASP ZAP)
      • SCA: finds known-vulnerable third-party dependencies and licence issues (Dependabot, Snyk, Trivy)
      IntermediateHow do you manage secrets for applications?

      Store them in a dedicated secrets manager (Vault, AWS Secrets Manager, GCP Secret Manager). Inject them at runtime via short-lived credentials, the Kubernetes External Secrets Operator or a CSI driver. Never commit them or bake them into images. Rotate automatically, audit access, and prefer dynamic secrets where possible.

      AdvancedWhat is software supply chain security, and what is an SBOM?

      It means protecting everything that goes into your software: dependencies, build systems and artifacts. Key practices: pinned dependencies, isolated reproducible builds, signed artifacts (Sigstore/Cosign), provenance attestations (SLSA) and admission policies that verify signatures. An SBOM (SPDX or CycloneDX) lists every component in an artifact, so you can instantly answer "are we affected by this CVE?"

      🧠 Scenarios & Behavioural (5)

      IntermediateProduction latency doubled after a deploy. What do you do?
      1. Mitigate: if the timing clearly matches the deploy, roll back first and investigate after.
      2. Confirm with dashboards: which endpoints, which percentiles, all instances or some?
      3. Diff the release: code, config, dependency versions, resource limits.
      4. Use traces to find the slow span (database query, downstream call, lock).
      5. Fix, add a test or alert that would have caught it, and write it up.
      IntermediateYour CI pipeline takes 40 minutes. How would you speed it up?
      • Measure each stage first, and fix the biggest one
      • Cache dependencies and Docker layers; use BuildKit and remote cache
      • Parallelise and shard tests; run only affected tests in monorepos
      • Run fast checks first so failures surface in minutes
      • Bigger or self-hosted runners for heavy jobs; remove redundant steps
      • Move slow end-to-end suites to post-merge or nightly with clear ownership
      BeginnerTell me about a time you automated something manual.

      Use the STAR format: Situation, Task, Action, Result. Quantify the result ("cut release time from 2 hours to 10 minutes", "removed 5 hours of toil per week"). If you lack work experience, use one of your portfolio projects: what was hard, what you'd do differently.

      IntermediateTell me about an outage you caused or handled.

      Interviewers want ownership and learning, not perfection. Describe the impact, how you detected and mitigated it, the root cause, and the systemic fix (a test, alert, guardrail or process change). Keep it blameless, even about yourself.

      BeginnerWhy DevOps? Why this role?

      Connect your motivation to outcomes: faster, safer delivery, and reducing toil for developers. Mention something specific about the company's stack or engineering blog, and one concrete thing you've built that shows you enjoy this work.
