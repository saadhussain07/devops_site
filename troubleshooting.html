      Troubleshooting Playbooks

      23 of the most common production failures in Kubernetes, Docker, Terraform, CI/CD and Linux, each with copy-paste diagnosis commands, likely causes and fixes.

      1 · StabiliseMitigate user impact first: roll back, fail over or scale.
      2 · ObserveRead events, logs and metrics before touching anything.
      3 · HypothesiseWhat changed? Form one theory and test it.
      4 · FixChange one thing at a time and verify.
      5 · PreventAdd the alert, test or guardrail that would have caught it.

      ☸️ Kubernetes (8)

      KubernetesCrashLoopBackOff

      Symptom

      Pod status shows CrashLoopBackOff and the RESTARTS count keeps climbing.

      Diagnose

      kubectl get pod <pod> -o wide
kubectl describe pod <pod>              # Last State, Exit Code, Events
kubectl logs <pod> --previous           # logs from the crashed container
kubectl get pod <pod> -o jsonpath='{.status.containerStatuses[0].lastState}'

      Likely causes & fixes

      CauseFix
      App exits on startup (exit code 1): bad config, missing env var or secret, can't reach a dependencyRead logs --previous, fix the config or Secret, and make the app retry its dependencies instead of exiting.
      Exit code 137 / reason OOMKilledSee OOMKilled: raise the memory limit or fix the leak.
      Liveness probe fails (Events show "Liveness probe failed")Wrong path or port, or it fires before the app is up. Add a startupProbe or raise initialDelaySeconds.
      Command finishes immediately (exit code 0)The main process must stay in the foreground. Fix command/args or the image's CMD.

      Prevent it

      Validate config at startup with clear error messages, use startup probes for slow apps, and keep liveness probes free of external dependencies.

      KubernetesImagePullBackOff / ErrImagePull

      Symptom

      Pod stuck in ImagePullBackOff or ErrImagePull; containers never start.

      Diagnose

      kubectl describe pod <pod> | sed -n '/Events/,$p'
# look for: "not found", "unauthorized", "manifest unknown", "i/o timeout"
kubectl get pod <pod> -o jsonpath='{.spec.containers[*].image}'

      Likely causes & fixes

      CauseFix
      Typo in the image name or tag, or the tag was never pushedCheck the exact reference with docker manifest inspect <image>; fix the tag in your manifest or values.
      Private registry without credentials ("unauthorized")Create a docker-registry Secret and reference it in imagePullSecrets, or grant the node role pull access (ECR).
      Architecture mismatch ("no matching manifest for linux/arm64")Build multi-arch with docker buildx build --platform linux/amd64,linux/arm64.
      Nodes can't reach the registry (timeout)Check NAT, egress firewalls, proxy settings, or VPC endpoints for ECR.

      Prevent it

      Tag images with immutable commit SHAs, never latest, and have CI verify the image exists before deploying.

      KubernetesPod stuck in Pending

      Symptom

      Pod stays Pending and is never scheduled to a node.

      Diagnose

      kubectl describe pod <pod>        # Events: "0/3 nodes are available: ..."
kubectl get nodes
kubectl describe node <node> | sed -n '/Allocated resources/,/Events/p'
kubectl get pvc

      Likely causes & fixes

      CauseFix
      Insufficient cpu/memory: requests exceed free capacity on every nodeLower the requests, add nodes, or enable a Cluster Autoscaler or Karpenter.
      Taints with no matching tolerations, or a nodeSelector/affinity nothing matchesFix the selector, or add a toleration. Check with kubectl get nodes --show-labels.
      Unbound PersistentVolumeClaimSee PVC Pending.
      ResourceQuota exceeded in the namespacekubectl describe quota -n <ns>, then raise the quota or reduce usage.

      Prevent it

      Set realistic requests from observed usage, and alert on unschedulable pods (kube_pod_status_phase{phase="Pending"}).

      KubernetesOOMKilled

      Symptom

      Container restarts with Reason: OOMKilled and exit code 137.

      Diagnose

      kubectl describe pod <pod> | grep -A5 'Last State'
kubectl top pod <pod> --containers
# Prometheus: container_memory_working_set_bytes vs the limit

      Likely causes & fixes

      CauseFix
      Memory limit is lower than what the app actually needsRaise resources.limits.memory based on observed peak plus headroom.
      Runtime not container-aware (e.g. JVM heap sized from host RAM)Use -XX:MaxRAMPercentage=75 for Java, or set GOMEMLIMIT for Go, so the runtime respects the limit.
      Memory leak: usage climbs steadily until the killProfile the app (heap dumps, pprof) and fix it. Restarting only hides the problem.

      Prevent it

      Alert when working-set memory exceeds 90% of the limit, and load-test new releases.

      KubernetesService returns 503 / has no endpoints

      Symptom

      Ingress returns 502/503, or curl to the Service times out, while the pods look Running.

      Diagnose

      kubectl get endpointslices -l kubernetes.io/service-name=<svc>
kubectl get svc <svc> -o yaml | grep -A3 selector
kubectl get pods --show-labels
kubectl get pods   # READY column, e.g. 0/1 means readiness is failing

      Likely causes & fixes

      CauseFix
      Service selector doesn't match the pod labelsMake spec.selector match the pod template labels exactly.
      Pods not Ready (failing readiness probe)kubectl describe pod shows the probe error. Fix the endpoint or the timing.
      targetPort doesn't match the port the container listens onAlign targetPort with containerPort and the app's actual listen port.
      App listens on 127.0.0.1 inside the containerBind to 0.0.0.0.

      Prevent it

      Use named ports, add a smoke test after each deploy, and alert on Services with zero ready endpoints.

      KubernetesCreateContainerConfigError

      Symptom

      Pod shows CreateContainerConfigError and never starts.

      Diagnose

      kubectl describe pod <pod>   # e.g. secret "db-creds" not found
kubectl get secret,configmap -n <ns>

      Likely causes & fixes

      CauseFix
      Referenced Secret or ConfigMap doesn't exist in this namespaceCreate it in the same namespace, or fix the name.
      Referenced key missing from the Secret or ConfigMapCheck the keys with kubectl get secret x -o jsonpath='{.data}'.
      runAsNonRoot: true but the image runs as rootSet USER 10001 in the Dockerfile, or set runAsUser.

      Prevent it

      Deploy Secrets (via External Secrets) before the apps that use them, and use Helm or Kustomize so the names stay consistent.

      KubernetesNode NotReady

      Symptom

      kubectl get nodes shows a node as NotReady; its pods get evicted or rescheduled.

      Diagnose

      kubectl describe node <node>   # Conditions: MemoryPressure, DiskPressure, PIDPressure
# on the node:
systemctl status kubelet containerd
journalctl -u kubelet --since "30 min ago"
df -h; free -m

      Likely causes & fixes

      CauseFix
      Disk or memory pressureClean up images and logs (crictl rmi --prune), and tune kubelet eviction thresholds.
      kubelet or container runtime crashedRestart it and read the journal logs for the cause (certificates, config, OOM).
      Network/CNI failure, or the node can't reach the API serverCheck the CNI pods on that node, security groups and routes.
      Expired kubelet certificatesEnable certificate rotation; on self-managed clusters renew with kubeadm certs.

      Prevent it

      Use managed node groups with auto-repair, alert on node conditions, and keep reserved resources for system daemons.

      KubernetesPVC Pending

      Symptom

      PersistentVolumeClaim stays Pending and its pod is stuck.

      Diagnose

      kubectl describe pvc <pvc>
kubectl get storageclass
kubectl get pods -n kube-system | grep -i csi

      Likely causes & fixes

      CauseFix
      No default StorageClass, or the name is wrongSet storageClassName, or mark a default class.
      WaitForFirstConsumer binding (this is normal)It binds once a pod that uses it is scheduled. Check the pod instead.
      CSI driver not installed or lacking cloud permissions (e.g. EBS CSI on EKS)Install the driver add-on and give it an IAM role (IRSA or Pod Identity).
      Volume zone doesn't match the node's zoneUse topology-aware StorageClasses and pin StatefulSets to zones.

      Prevent it

      Install storage drivers through IaC, and test a PVC in every new cluster.

      🐳 Docker (4)

      DockerContainer exits immediately

      Symptom

      docker run -d returns, but docker ps shows nothing; docker ps -a shows Exited (0) or (1).

      Diagnose

      docker ps -a
docker logs <container>
docker inspect <container> --format '{{.State.ExitCode}} {{.State.Error}}'
docker run -it --entrypoint sh <image>   # poke around inside

      Likely causes & fixes

      CauseFix
      The main process ends (a script finishes, or a daemon forks into the background)Run the process in the foreground (e.g. nginx -g 'daemon off;').
      App crashes because of missing env vars, files or configRead the logs, then pass -e/--env-file or mount the config.
      Wrong CMD/ENTRYPOINT, or shell form vs exec form problemsUse the exec form ["node","server.js"].

      Prevent it

      Add a HEALTHCHECK, and log a clear message before exiting on bad config.

      DockerNo space left on device

      Symptom

      Builds or containers fail with no space left on device.

      Diagnose

      docker system df
df -h /var/lib/docker
docker system prune            # stopped containers, dangling images, unused networks
docker builder prune           # build cache
docker image prune -a          # ALL unused images (be careful)

      Likely causes & fixes

      CauseFix
      Old images and build cache piling up (common on CI runners)Prune on a schedule, e.g. docker system prune -af --filter "until=72h".
      Huge container logs (json-file driver with no rotation)Set log-opts max-size/max-file in daemon.json.
      Orphaned volumesdocker volume ls -f dangling=true, then docker volume prune.

      Prevent it

      Configure log rotation, alert on disk usage, and put /var/lib/docker on its own volume.

      DockerPort is already allocated

      Symptom

      Bind for 0.0.0.0:8080 failed: port is already allocated.

      Diagnose

      docker ps --format '{{.Names}} {{.Ports}}' | grep 8080
sudo ss -tlnp | grep :8080

      Likely causes & fixes

      CauseFix
      Another container is publishing the same host portStop it, or map a different port: -p 8081:8080.
      A host process is already listening on the portStop that service or choose another port.

      Prevent it

      Use Compose project names and avoid hard-coding host ports in shared environments.

      DockerPermission denied on a mounted volume

      Symptom

      The app can't write to a bind-mounted directory: EACCES or permission denied.

      Diagnose

      docker exec <c> id
docker exec <c> ls -ln /data
ls -ln ./data   # on the host

      Likely causes & fixes

      CauseFix
      Container user's UID doesn't own the host directorychown the host directory to the container UID, or run with --user $(id -u):$(id -g).
      SELinux blocks the mount (Fedora/RHEL)Add :z or :Z to the volume flag.
      Read-only mountRemove :ro if writes are actually intended.

      Prevent it

      Use named volumes for app data and create directories with the right owner in the Dockerfile.

      🏗️ Terraform (3)

      TerraformError acquiring the state lock

      Symptom

      Error: Error acquiring the state lock with a lock ID, who holds it and when.

      Diagnose

      # Is someone (or a CI job) actually running?
# Check the lock info printed in the error: Who / Created / Operation
terraform force-unlock <LOCK_ID>   # only when you're SURE nothing is running

      Likely causes & fixes

      CauseFix
      Another apply or plan is genuinely runningWait for it to finish. Do not unlock.
      A previous run crashed or was cancelled and left a stale lockConfirm nothing is running, then run terraform force-unlock <ID>.
      CI jobs running concurrently on the same stateSerialise them with CI concurrency groups per state.

      Prevent it

      Run applies only from CI, with a concurrency limit of one per state file.

      TerraformResource already exists

      Symptom

      Apply fails with "already exists" (e.g. BucketAlreadyOwnedByYou or EntityAlreadyExists).

      Diagnose

      terraform state list | grep <name>
# Terraform 1.5+: declarative import
# import { to = aws_s3_bucket.logs  id = "my-logs-bucket" }
terraform plan -generate-config-out=generated.tf

      Likely causes & fixes

      CauseFix
      The resource was created manually or by another stackBring it under management with an import block, then plan until there are no changes.
      State was lost or someone ran state rmRe-import it. Restore state from the versioned S3 bucket if needed.
      Two configurations manage the same resourcePick one owner; remove it from the other with a removed block or state rm.

      Prevent it

      Make all changes through code, enable state bucket versioning, and use unique naming with environment prefixes.

      TerraformPlan shows changes nobody made (drift)

      Symptom

      terraform plan wants to modify or replace resources even though the code didn't change.

      Diagnose

      terraform plan -refresh-only     # see what changed outside Terraform
terraform plan -out=tf.plan && terraform show tf.plan

      Likely causes & fixes

      CauseFix
      Someone changed it in the consoleEither codify the change or let apply revert it. Find out who in CloudTrail.
      Provider upgrade changed defaultsPin provider versions, and read changelogs before bumping them.
      Attributes managed by something else (autoscaling, tags added by tooling)Use lifecycle { ignore_changes = [...] } for those attributes only.

      Prevent it

      Run a scheduled drift-detection plan, give people read-only console access, and use policy guardrails.

      🔁 CI/CD (3)

      CI/CDWorks locally, fails in CI

      Symptom

      Tests or builds pass on your laptop but fail in the pipeline.

      Diagnose

      # Reproduce CI exactly:
docker run --rm -it -v "$PWD":/w -w /w <same-image-as-ci> bash
# compare: tool versions, env vars, OS/arch, timezone, locale
env | sort > ci-env.txt   # print in CI too, then diff

      Likely causes & fixes

      CauseFix
      Different tool or runtime versionsPin versions (.nvmrc, .tool-versions, lockfiles) and use npm ci, not npm install.
      Files that exist locally but aren't committed (.env, generated code)Run git status --ignored; commit what's needed, or generate it in CI.
      Case-sensitive filesystem in CI (Linux) vs macOS/WindowsFix import paths so the case matches the filenames exactly.
      Missing secrets or variables in CI, or secrets not available to fork PRsAdd them at the repo or environment level; design PR checks that don't need secrets.

      Prevent it

      Run builds in containers locally and in CI, and commit lockfiles.

      CI/CDFlaky tests

      Symptom

      The same commit passes and fails randomly.

      Diagnose

      # Re-run the suspect test many times
for i in $(seq 1 50); do npm test -- -t "name" || break; done
# look for: sleeps, shared state, test order, time, network

      Likely causes & fixes

      CauseFix
      Timing assumptions (sleep, race conditions)Wait on conditions (poll or await events), not fixed delays.
      Shared state between tests (DB rows, globals, files)Isolate: a fresh fixture per test, unique names, transactions rolled back.
      Real network or external servicesMock them, or use test containers.
      Dependence on test orderRun with a random order to expose it, then fix the hidden dependency.

      Prevent it

      Track flaky rates, quarantine with an owner and a deadline (never silently skip), and fix the root cause.

      CI/CD403 / denied when pushing an image

      Symptom

      denied: permission_denied, 403 Forbidden or unauthorized on docker push.

      Diagnose

      # GitHub Actions + GHCR: does the job have package write permission?
#   permissions:
#     packages: write
docker login ghcr.io -u $GITHUB_ACTOR --password-stdin <<< "$GITHUB_TOKEN"
# image name must be lowercase: ghcr.io/owner/repo

      Likely causes & fixes

      CauseFix
      Workflow permissions don't include packages: writeAdd it at the job or workflow level.
      Image name has uppercase lettersLowercase it, e.g. ${GITHUB_REPOSITORY,,} in Bash.
      The package belongs to another repo or org without accessGrant the repo access in the package settings.
      Expired or wrong token (Docker Hub, ECR login expires after 12h)Refresh the login on every run; prefer OIDC roles for ECR.

      Prevent it

      Use OIDC and short-lived tokens, and set least-privilege permissions: on every workflow.

      🐧 Linux & Network (5)

      Linux & NetworkHigh CPU usage

      Symptom

      Load is high, the app is slow, and alerts fire for CPU above 90%.

      Diagnose

      uptime                         # load vs number of cores (nproc)
top -o %CPU                    # or htop
pidstat 1 5                    # per-process over time
vmstat 1 5                     # us/sy/wa/st columns
perf top -p <pid>              # hot functions

      Likely causes & fixes

      CauseFix
      One runaway process (busy loop, regex, GC thrash)Profile it (perf, language profiler), fix it, or restart as a stopgap.
      High wa (iowait), not CPU-bound at allIt's disk I/O. Use iostat -x 1 and iotop.
      High st (steal) on a VMNoisy neighbour or burstable credits exhausted (AWS t-series). Move to a larger or non-burstable instance.
      Real demand growthScale out or optimise the hot path.

      Prevent it

      Alert on saturation trends, keep CPU profiling available in production, and load-test before launches.

      Linux & NetworkDisk full

      Symptom

      Writes fail with No space left on device.

      Diagnose

      df -h                          # which filesystem?
df -i                          # inodes exhausted?
sudo du -xh / --max-depth=2 2>/dev/null | sort -h | tail -20
sudo lsof +L1                  # deleted files still held open
journalctl --disk-usage

      Likely causes & fixes

      CauseFix
      Logs growing without rotationConfigure logrotate, and cap journald with SystemMaxUse=.
      Deleted file still held open by a processRestart the process, or truncate via /proc/<pid>/fd/<n>.
      Inodes exhausted by millions of tiny filesFind the directory with find / -xdev -type d -size +1M and clean up (sessions, caches).
      Docker or containerd dataSee Docker: No space left.

      Prevent it

      Alert at 80% for space and inodes, and rotate logs everywhere.

      Linux & NetworkConnection refused vs connection timed out

      Symptom

      Clients can't connect to a service.

      Diagnose

      nc -zv <host> <port>
curl -v http://<host>:<port>/health
sudo ss -tlnp | grep <port>       # on the server
sudo iptables -L -n | head        # or nft list ruleset

      Likely causes & fixes

      CauseFix
      Refused: the host is reachable but nothing is listening (or it's bound to 127.0.0.1)Start the service, or bind it to 0.0.0.0 or the right interface.
      Timed out: packets are dropped (security group, NACL, firewall or routing)Check firewall rules along the path, and whether the source IP is allowed.
      Connection reset: the peer closed it (TLS mismatch, proxy, app crash)Check the app and proxy logs, and the protocol (HTTP vs HTTPS).

      Prevent it

      Use health checks and synthetic probes, and keep firewall rules in code.

      Linux & NetworkDNS resolution failures

      Symptom

      Could not resolve host, NXDOMAIN or intermittent SERVFAIL.

      Diagnose

      dig +short <name>
dig <name> @8.8.8.8          # compare with a public resolver
cat /etc/resolv.conf
# in Kubernetes:
kubectl run -it --rm dnsutils --image=registry.k8s.io/e2e-test-images/agnhost:2.39 -- nslookup <svc>.<ns>.svc.cluster.local
kubectl -n kube-system logs -l k8s-app=kube-dns

      Likely causes & fixes

      CauseFix
      Record missing or wrong (typo, wrong zone, not propagated)Fix the record; remember resolvers cache it for the old TTL.
      Wrong resolver in /etc/resolv.confFix the DHCP or systemd-resolved configuration.
      Kubernetes: wrong namespace in a short name, or CoreDNS overloadedUse svc.namespace, scale CoreDNS, and consider NodeLocal DNSCache.
      ndots:5 causing slow lookups for external namesUse fully qualified names with a trailing dot, or tune dnsConfig.

      Prevent it

      Monitor DNS latency and error rates, and lower TTLs before migrations.

      Linux & NetworkTLS: x509 certificate errors

      Symptom

      x509: certificate has expired, certificate signed by unknown authority or certificate is valid for X, not Y.

      Diagnose

      openssl s_client -connect <host>:443 -servername <host> </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates -ext subjectAltName
curl -vI https://<host>

      Likely causes & fixes

      CauseFix
      Certificate expiredRenew it; automate with cert-manager, ACM or certbot timers.
      Incomplete chain (server doesn't send the intermediate)Serve the full chain (fullchain.pem).
      Private or internal CA not trusted by the clientAdd the CA to the trust store (the image's ca-certificates, or a mounted bundle). Never use --insecure in production.
      Hostname not in the SAN listReissue with the correct SANs, or use the right hostname. SNI matters behind shared IPs.

      Prevent it

      Automate renewal and alert on expiry 21 days ahead (e.g. the blackbox exporter's probe_ssl_earliest_cert_expiry).
